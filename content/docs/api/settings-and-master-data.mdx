# Settings and Master Data API

The POS app is configured almost entirely from the server. An owner changes a setting in the admin panel, and the POS picks it up on the next startup sync, store switch, or **Offline Data > Sync**. This page lists every configuration endpoint the app calls, with the response shape and what the app does with it.

For the full list of setting codes, defaults and their effect on screens, see [Settings reference](/docs/pos-app/settings-reference).

All calls send `X-Tenant`, and `Authorization: Bearer <access-token>` once signed in (see [API overview](/docs/api)). Localised calls also send `?locale=` and `Accept-Language`.

## Startup sync order

After **Select Store**, the app shows the startup sync steps. The configuration calls on this page run in these steps:

| Startup step | Endpoint(s) |
|---|---|
| Permissions | `roles/list` |
| Delivery methods | `logistics/list-delivery-methods` |
| General settings | `general` |
| Applying preferences | `website-settings` |
| Branding | `admin-settings` (sidebar logo) |
| Banks | `get-banks` |
| Payment methods | `master-data-values?code=PAYMENT_METHOD` |
| Stock grouping | `master-data-values?code=STOCK_GROUPING_FIELDS` |
| Store | `stores/get-stores` |
| Units | `product/list-units` |
| Racks | `master-data-values?code=RACKS` |
| Document configs | `document/document-configs`, `document/printer-settings` |

Other steps (customers, invoices, voucher types, users, suppliers, categories, products, realtime sync) are covered on their own API pages.

## GET /api/v1/website-settings

**Purpose:** the company settings ("company props") that switch POS features on or off, plus a few synthetic values (company name, theme, currency, discount and ZATCA flags) and translated website texts.

**Used by:** startup "general settings" step; **Offline Data > App / website settings**. Results are cached on the device.

**Query parameters**

| Name | Type | Required | Description |
|---|---|---|---|
| `store_id` | integer | no | Active store (the app always sends it) |
| `locale` | string | no | `en`, `ar`, `ml` - for translated texts |

**Response (200)** (trimmed; 127 entries in the demo)

```json
{
  "status": "success",
  "message": "Filtered Website Settings",
  "data": [
    { "name": "Show Cart Control", "code": "SHOW_CART_CONTROL", "value": "", "status": "true" },
    { "name": "Recent Products Section", "code": "RECENT_PRODUCTS_SECTION", "value": "", "status": "true" },
    { "name": "Currency", "code": "CURRENCY", "value": "SAR", "status": "true" },
    { "name": "Default Payment Method", "code": "DEFAULT_PAYMENT_METHOD", "value": "CASH", "status": "true" },
    { "name": "Free Delivery Minimum Amount", "code": "FREE_DELIVERY_MINIMUM_AMOUNT", "value": "0", "status": "false" }
  ]
}
```

The first two rows are from the demo capture; the other three show the shape of value-type settings.

**How to read an entry**

- `status` switches a feature. The app treats `true`, `"true"`, `"1"` and `1` as on. Anything else is off.
- `value` carries text or numbers, for example `CURRENCY` = `SAR`, `DEFAULT_PAYMENT_METHOD` = `CASH`, `AUTO_ASSIGN_DEFAULT_CUSTOMER` = a phone number, `POS_AUTHENTICATE_CLEARCART` = the security key.
- Some settings use both: `FREE_DELIVERY_MINIMUM_AMOUNT` charges delivery only while `status` is on, and makes delivery free when the net total reaches `value`.
- A code missing from the response uses the app default (for example `POS_OFFLINE_SALES` defaults to on, `SHOW_CONFIRM_ORDER_BUTTON` to on).

**Most important codes for the POS** (full table in [Settings reference](/docs/pos-app/settings-reference)):

| Code | Effect in the app |
|---|---|
| `POS_OFFLINE_SALES` | On (default): offline-first confirm. Off: wait for the server before printing |
| `SHOW_CONFIRM_ORDER_BUTTON`, `SHOW_CONFIRM_ORDER_AND_PRINT_BUTTON`, `SHOW_CONFIRM_WHATSAPP_BUTTON` | Show **Confirm Order**, **Confirm and Print**, **Confirm & Whatsapp** |
| `DISCOUNT_AND_COUPON` | Shows the **Discount** (F10) panel |
| `FREE_DELIVERY_MINIMUM_AMOUNT` | Delivery charges apply only while enabled |
| `PRICE_ROUND_OFF` | Rounds the net total to a whole number |
| `ZATCA_PHASE_1`, `ZATCA_PHASE_2` | ZATCA QR, VAT/CR customer fields, Phase 2 actions |
| `COMPULSORY_SHIFT_OPEN`, `COMPULSORY_DAY_CLOSE_REGISTER` | Force Open Shift / pending Day Close |
| `ENABLE_KOT_PRINT`, `ENABLE_SEND_TO_KITCHEN_BUTTON`, `ENABLE_KOT_BILL_BUTTON` | Restaurant kitchen ticket behaviour |
| `DASHBOARD_DEFAULT_PERIOD` | Default dashboard period |
| `COMPANY_SUBSCRIPTION_STATUS` (+ `_MESSAGE`, `_VALID_UNTIL`, `_MANAGE_URL`) | Fallback subscription status |

## GET /api/v1/general

**Purpose:** general (tenant-wide) settings. Today the endpoint returns only stock tracking.

**Used by:** startup "general settings" step; **Offline Data > General settings**.

**Query parameters:** `store_id` (optional).

**Response (200)**

```json
{
  "status": "success",
  "message": "Success",
  "data": {
    "stock_enabled": true
  }
}
```

- `stock_enabled` turns stock tracking on or off. The app caches it as `general_stock_enabled`.
- The website setting `POS_HIDE_NONSTOCK_PRODUCT` hides zero-stock products **only** when `stock_enabled` is also true.
- No authentication is required on the server for this endpoint.

## GET /api/v1/admin-settings

**Purpose:** platform-wide branding (not per tenant).

**Used by:** startup "branding" step. The app reads only `SIDEBAR_LOGO` and caches the image for the side menu.

**Query parameters**

| Name | Type | Required | Description |
|---|---|---|---|
| `code` | comma list | no | Limit to codes, for example `SIDEBAR_LOGO,FAVICON_ICON` |

**Response (200)**

```json
{
  "status": "success",
  "message": "Admin Settings retrieved successfully",
  "data": [
    { "name": "Sidebar Logo", "code": "SIDEBAR_LOGO", "type": "file", "value": "{{server}}/storage/admin-settings/<file>.jpg" },
    { "name": "Favicon Icon", "code": "FAVICON_ICON", "type": "file", "value": "" }
  ]
}
```

File values are returned as full URLs.

## GET /api/v1/company/prop-names

**Purpose:** read raw company props by code. The POS app does **not** call this endpoint; it gets the same values through `website-settings`. It is listed for integrators.

**Query parameters:** `propCode` (optional, one code, for example `TERMS_AND_CONDITIONS`).

**Response:** `{"status":"success","message":"Success","data":[{"name","code","value","status":"true"|"false"}]}`. `COMPANY_LOGO` and `COMPANY_FAVICON` come back as URLs.

## GET /api/v1/master-data-values

**Purpose:** the company's lookup lists (payment methods, racks, tables, denominations and more).

**Used by:** checkout, stock, purchase, restaurant, day close, expenses and delivery dialogs.

**Query parameters**

| Name | Type | Required | Description |
|---|---|---|---|
| `code` | string | yes | Master data code, see table below |
| `store_id` | integer | no | Active store |
| `locale` | string | no | Language for labels |

**Response (200)** (PAYMENT_METHOD, trimmed: one value shown, translation rows shortened)

```json
{
  "status": "success",
  "message": "Filtered Master Data Values",
  "meta": {
    "available_languages": ["ar", "en", "..."],
    "requested_language": "*"
  },
  "data": [
    {
      "id": 7973,
      "master_data_id": 16,
      "value": "CARD",
      "description": "card",
      "code": "CARD",
      "label": "card",
      "translations": [
        { "locale": "ar", "key": "description", "value": "بطاقة" },
        { "locale": "ml", "key": "description", "value": "കാർഡ്" }
      ],
      "master_data": {
        "id": 16,
        "name": "Payment Methods",
        "code": "PAYMENT_METHOD",
        "type": "LST"
      }
    },
    {
      "id": 7974,
      "value": "CASH",
      "description": "cash",
      "code": "CASH",
      "label": "cash",
      "translations": [ { "locale": "ar", "key": "description", "value": "نقدًا" } ]
    }
  ]
}
```

**Errors**

| Case | HTTP | Body |
|---|---|---|
| `code` missing | 400 | `{"success":false,"message":"Code parameter is required","data":[]}` |
| Unknown code for this company | 404 | `{"success":false,"message":"Master data not found","data":[]}` |

Only active values (`status` true) are returned.

**Codes the app uses**

| Code | Used for | Notes |
|---|---|---|
| `PAYMENT_METHOD` | Payment dialog methods (cash, card, ...) | Orders store the value **id** (7973 = CARD, 7974 = CASH in the demo). Optional fields `enabled`, `sort_order`, `icon_key`, `behavior` (`collected`, `credit`, `terminal`), `requires_reference`. The app always adds **Credit** (sell on credit) |
| `STOCK_GROUPING_FIELDS` | How stock batches are grouped into one billing line | Values PRICE, MRP, PURCHASE_PRICE, UNIT, HSN_CODE, TAX_RATE, WHOLESALE_PRICE, WHOLESALE_MIN_UNIT, EXPIRING_DATE. App default: price + unit |
| `CASH_DENOMINATIONS` | Open Shift and Day Close cash counting | Seeded 500, 200, 100, 50, 20, 10, 5, 1 |
| `KOT_ITEM_NOTE_OPTIONS` | Quick notes on restaurant items (for example NO ICE, EXTRA SPICY, LESS SUGAR) | Not seeded; each company creates it |
| `RACKS` | Rack picker on stock and purchase | Seeded RACK 1-10 |
| `TABLE_LIST` | Restaurant tables | |
| `EXPENSE_CATEGORY` / `EXPENSE_CATEGORIES` | Expense category picker | |
| `SHIPPING_METHOD` | Create Delivery dialog | parcel, speed_post, registered_parcel, express |
| `TRANSPORT_MODE` | Create Delivery dialog | surface, air, ship |
| `DELIVERY_PAYMENT_MODE` | Create Delivery dialog | Prepaid, COD, Open Box Delivery |

`GET /api/v1/master-data` and `GET /api/v1/master-data/{code}` also exist (token required) but the POS uses `master-data-values`.

**Used by:** every print and PDF (receipts, A4/A5 invoices, return bills, quotations, KOT, barcodes), **Printer Settings > Resync Doc**, **Offline Data > Document configurations**.

|---|---|---|---|
| `store_id` | integer | no | Active store |
| `type` | string | no | One document type, for example `bill`. Without it all types are returned |
| `language` | string | no | Document language, for example `en_ar` |

**How the app applies it**

| Server field | Device preference |
|---|---|
| `b2c_paper_size` | `default_paper_size` |
| `b2c_template` | `billing_receipt_theme` |
| `b2b_paper_size` | `default_paper_size_b2b` |
| `b2b_template` | `billing_receipt_theme_b2b` |

- Values are checked against `options`. Thermal sizes (58/80/112 mm) use `thermal_templates`; A4/A5 use `paper_templates`.
- The server value is applied only where the user has **not** picked a value on this device. At store selection the app forces the server values.

## POST /api/v1/translate

**Purpose:** machine-translate a product or category name.

**Used by:** the translate button next to Arabic / Malayalam names on **Add New Category**, **Create New Product** and product details.

**Request body**

```json
{
  "target_lang": "ar",
  "text": "classic chicken bucket"
}
```

**Response (200):** `{"success": true, "data": {"translated_text": "..."}}`. When translation fails the app leaves the field unchanged.
