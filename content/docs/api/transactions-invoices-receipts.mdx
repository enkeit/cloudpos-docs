# Transactions, Invoices and Receipts API

These endpoints power the **Transactions** menu (**Invoice**, **Receipts**, **Customer Voucher**, **Proforma Invoice**, **Expense**), **Party Accounts > Customer Transactions**, the **Customer Transaction Reports** and the cash/bank figures on the dashboard.

All paths are relative to `{{server}}`. Send `X-Tenant: <your-tenant-key>`, `Authorization: Bearer <access-token>` and `Content-Type: application/json`. Most calls add `store_id` = the active store.

## How a sale shows up here

When the demo order **ORD-004851** (receipt number `2-11-261027-0003`, total 658.00, tax 100.37) was confirmed, the server created automatically:

- invoice **INV-OR1002060** for 658.00, linked to the offline receipt number, ZATCA status **NOT SENT**;
- receipt **RCP1001953** with the payment breakdown **cash 258.00 + card 400.00** (cash is stored net of the 42.00 change);
- ledger lines for the customer (invoice debit, receipt credits) and a cost-of-goods line.

Invoice, receipt and voucher numbers use the company prefixes `INVOICE_PREFIX` (INV), `RECEIPT_PREFIX` (RCP) and `VOUCHER_PREFIX` (VCH).

## GET /api/v1/invoice/list-invoices

| Name | Type | Notes |
|---|---|---|
| `name` (or `customer_name`) | string | Customer name |
| `phone` (or `customer_phone`) | string | Customer phone |
| `customer_id` | integer | One customer |
| `invoice_number` | string | Partial match |
| `order_number` (or `order_reference`, `receipt_number`) | string | Server order number **or** printed offline receipt number |
| `type` | string | Invoice type, for example `order` |
| `zatca_status` | string | `sent`, `not_sent` or `failed` (see below) |
| `date_from`, `date_to` | date | Uses the linked transaction date (or the invoice's own date); the app's **Today** chip sends today for both |
| `per_page` | integer | Default 20 (the app uses up to 1000 for export) |
| `page` | integer | Page |
| `store_id` | integer | Active store |

ZATCA filter values:

| UI filter | Sent as | Server meaning |
|---|---|---|
| Sent / Success | `sent` | Has a successful ZATCA submission |
| Not Sent | `not_sent` | Never submitted |
| Failed | `failed` | Has a failed submission and no successful one |

### Response

```json
{
  "status": "success",
  "message": "Invoices listed successfully",
  "data": {
    "current_page": 1,
    "data": [
      {
        "id": 6816,
        "invoice_number": "INV-OR1002060",
        "type": "order",
        "amount": "658.000",
        "total_tax": "100.370",
        "total_discount": "0.000",
        "invoice_date": "2026-10-27",
        "due_date": "2026-10-27",
        "customer_id": 2767,
        "customer_name": "Layla Al-Harbi",
        "paid_amount": "658.00",
        "balance_amount": 0,
        "order_number": "ORD-004851",
        "receipt_number": "2-11-261027-0003",
        "client_sale_id": "<uuid-v7>",
        "zatca_status": { "status": "not_sent", "zatca_status": null }
      }
    ],
    "per_page": 20,
    "last_page": 1,
    "total": 1
  }
}
```

*Illustrative row for the demo invoice (the captured response for its filter was empty). `paid_amount` is the sum of paid receipt payments; `balance_amount` = amount − paid.*

`zatca_status.status` is the latest submission's state (`success`, `failed`…) or `not_sent`; `zatca_status.zatca_status` is ZATCA's own reporting/clearance result.

## GET `/api/v1/invoice/invoice-details/{id}`

Returns the invoice with its customer, `invoice_items` and the order references.

```json
{
  "status": "success",
  "message": "Invoice details retrieved successfully",
  "data": {
    "id": 6816,
    "invoice_number": "INV-OR1002060",
    "amount": "658.000",
    "total_tax": "100.370",
    "order_number": "ORD-004851",
    "receipt_number": "2-11-261027-0003",
    "invoice_items": [
      { "item_name": "classic chicken bucket", "quantity": "2.000", "unit_amount": "186.441", "tax": "67.12", "total_amount": "440.000" },
      { "item_name": "crispy chicken bucket", "quantity": "1.000", "unit_amount": "184.746", "tax": "33.25", "total_amount": "218.000" }
    ],
    "customer": { "id": 2767, "user": { "name": "Layla Al-Harbi", "phone": "0551234567" } }
  }
}
```

*Illustrative, trimmed. Line tax follows the tax-inclusive rule: 440 × 18 ÷ 118 = 67.12 and 218 × 18 ÷ 118 = 33.25.* Not found → `"Invoice not found"`.

## POST /api/v1/invoice/invoice-create

Creates a manual invoice (not from an order).

| Field | Required | Notes |
|---|---|---|
| `customer_id` | yes | Customer |
| `type` | yes | `order` or `other` |
| `invoice_date`, `due_date` | yes | Dates |
| `amount` | yes | Total |
| `status` | yes | `paid`, `pending` or `overdue` |
| `payment_method` | when `status` is `paid` | `PAYMENT_METHOD` id |
| `invoice_items` | yes | `[{item_name, unit_amount, tax, quantity, total_amount}]`; optional `tax_rate`, `tax_amount`, `unit_amount_includes_tax` |
| `coupon_id`, `flat_discount`, `percentage_discount`, `discount_amount` | no | Discount, sent only when used |

```json
{
  "customer_id": 2767,
  "type": "other",
  "due_date": "2026-11-03",
  "invoice_date": "2026-10-27",
  "amount": 236.0,
  "status": "pending",
  "payment_method": "<payment-method-id>",
  "invoice_items": [
    { "item_name": "Catering service", "unit_amount": 200, "tax": 18, "quantity": 1, "total_amount": 236 }
  ]
}
```

Validation errors → **422** `{"status":false,"message":"<first error>","errors":{...}}`. The app also blocks this call when the company subscription is blocked.

## POST /api/v1/receipt/create-receipt

Records money received from a customer, against invoices or as a general receipt.

**Used by:** Receipt List > **Create Receipt**.

| Field | Required | Notes |
|---|---|---|
| `customer_id` | yes | Customer |
| `store_id` | no | The app always sends the active store |
| `receipt_status` | yes | `paid`, `pending` or `cancelled` |
| `payment_reference` | no | Bank/card reference |
| `receipt_items` | yes | At least one |
| `receipt_items.*.item_type` | yes | `invoice` (needs `invoice_id`) or `general` (needs `description`) |
| `receipt_items.*.invoice_id` | for invoice | Invoice |
| `receipt_items.*.paid_amount` | yes | ≥ 0 |
| `receipt_items.*.status` | yes | `paid`, `refunded` or `waive` |
| `receipt_items.*.payment_date` | yes | Date |
| `receipt_items.*.payment_method` | no | `PAYMENT_METHOD` id |
| `receipt_items.*.description` | for general | Text |

```json
{
  "customer_id": "2767",
  "store_id": 2,
  "receipt_status": "paid",
  "payment_reference": "TXN-55120",
  "receipt_items": [
    { "item_type": "invoice", "invoice_id": 6830, "paid_amount": 236, "status": "paid", "payment_date": "2026-10-27", "payment_method": "<card-id>" }
  ]
}
```

Rules:

- **409** `"A paid receipt already exists for Invoice #… Cannot create another."` when the invoice is fully paid.
- **409** `"The entered amount is greater than the balance amount"` when paying more than is due.
- **422** with the first validation error in `message`.
- Invoices are locked while the receipt is created, so two counters cannot over-pay the same invoice.

## GET /api/v1/general-payment/account-options

Returns the accounts allowed for an entry type.

| Name | Notes |

## POST /api/v1/general-payment/create-general-payment

**Used by:** **Create Expense** (**Create** or **Create & create another**). The reference number (for example `EXP00120`) is generated by the server.

| Field | Required | Notes |
|---|---|---|
| `entry_type` | yes | `EXPENSE` from the expense screen |
| `payment_date` | yes | `yyyy-MM-dd` |
| `category` | yes | Master-data id from `EXPENSE_CATEGORY` |
| `description` | no | Description / vendor, up to 255 characters |
| `amount` | yes | ≥ 0.01 |
| `payment_method` | yes | `PAYMENT_METHOD` id |
| `expense_account_id` | no | Debit account (active company account) |
| `payment_account_id` | no | Credit account |
| `status` | no | App sends `SUCC` |
| `notes` | no | Up to 500 characters |
| `store_id` | no | The app adds the active store |

```json
{
  "entry_type": "EXPENSE",
  "payment_date": "2026-10-27",
  "category": "<category-id>",
  "description": "Electricity bill",
  "amount": 350.0,
  "payment_method": "<cash-id>",
  "expense_account_id": 31,
  "payment_account_id": 11,
  "status": "SUCC",
  "notes": "",
  "store_id": 2
}
```

Returns **201** `{"success":true,"message":"General payment created successfully","data":{...}}`. Validation errors → **422** `{"success":false,"message":"Validation failed","errors":{...}}`. Expenses are included in the day-close summary.
