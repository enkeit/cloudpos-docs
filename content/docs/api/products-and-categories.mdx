# Products and Categories API

These endpoints feed the product grid in **Billing**, the **Product List**, **Create New Product**, **Category List** and **Add New Category** screens, and the offline product cache.

All paths are relative to `{{server}}` (your tenant domain, found with `find-domain`, see [API overview](/docs/api)). Unless a section says otherwise, send:

| Header | Value |
|---|---|
| `X-Tenant` | `<your-tenant-key>` |
| `Authorization` | `Bearer <access-token>` (required on write endpoints and on `generate-barcode`) |
| `Content-Type` | `application/json` (multipart for category create and edit) |
| `Accept` | `application/json` (the app sends it on product create and edit so validation errors come back as JSON) |

The app adds `store_id` (the active store, for example `2` for "متجر النجمة Store") to almost every call.

| POST | `/api/v1/product/delete-product` | Delete action on Product List |

## GET /api/v1/product/executive/list-products

**Purpose:** returns sellable products with prices, taxes, stock batches, sale units and variants. This is the main product feed of the POS.

**Screens:** Billing product grid (desktop and phone), Product List, barcode scan in Billing, quick-pick tiles (`quick_access=true`), Settings > **Resync Products** and the **Offline Data** "Products" row.

**Authentication:** `X-Tenant` is enough. No bearer token is needed.

### Query parameters

| Param | Example | Effect |
|---|---|---|
| `store_id` | `2` | Stock rows and `number_of_products_available` are limited to this store. If the store has mapped categories, only products in those categories are returned. |
| `type` | `sellable` | `sellable` = only products whose category is sellable. `not_sellable` = purchasable categories. Default `all`. Offline sync uses `type=sellable`. |
| `page` | `7` | Page number. |
| `per_page` | `500` | Page size. Default 500, clamped to 1–500. |
| `list_all` | `true` | Returns every product without paging. |
| `name` | `bucket` | Matches product name, item code, SKU, HSN code and translated names. |
| `barcode` | `6271028081119` | Resolves the barcode (main, sale-unit, variant or scale barcode) to one product. An unknown barcode returns no products. For weighed barcodes the product carries `weight_info`. |
| `category_id` | `19` | Products of one category. |
| `quick_access` | `true` | Only products marked for quick access (the tiles that open **Select Price**). |
| `updated_at_range` | `2026-10-27T00:00:00,2026-10-27T15:00:00` | Delta sync: products (or their stock in this store) changed in the range. Also fills `deleted_product_ids`. A bad range returns `422`. |
| `price_range` | `100,300` | Products whose base price is in the range. |
| `sort_by` | `name` | One of `name`, `price`, `mrp`, `sort_order`, `created_at`, `updated_at`. Default `sort_order` then name. |
| `sort_order` | `asc` | `asc` or `desc`. |

The Product List screen also sends `filter_price`, `filter_created_by`, `filter_store` and `filter_supplier` from its filter panel.

### Product fields

| Field | Meaning |
|---|---|
| `product_id`, `category_id` | Ids. |
| `product_name`, `names` | Default name and translated names by language code (`en`, `ar`, …). |
| `barcode`, `sku`, `item_code`, `hsn_code` | Codes. `item_code` is shown only when **ITEM_CODE_ENABLED** is on. SKU is what the weigh-machine PLU export uses. |
| `price.base_price`, `price.total_price`, `price.standard_unit_price` | Selling price. Prices are tax-inclusive. `standard_unit_price` is the reference price before any offer. |
| `offer_price` | Price after the active offer for this store, when there is one. |
| `mrp`, `purchase_price`, `credit_price` | MRP, purchase price (shown only to users with purchase access), credit price. |
| `min_margin_percentage`, `min_margin_price` | Despite the names, these are the **maximum discount** caps (percent and amount) shown as "Max discount %" and "Max discount amount" on Create New Product. |
| `taxes[]` | Taxes that apply. `source` tells whether the tax came from the product or its category. |
| `sellable`, `purchasable` | From the category. |
| `number_of_products_available` | Total stock in the requested store. |
| `reorder_level` | Low-stock threshold used by stock lists and the Non-Stock Report. |
| `product_props[]` | Property values (`props_code`, `master_value`, `type`), for example `FOOD_TYPE` (VEG / NON_VEG) or `WARRANTY_IN_MONTH`. |
| `weight_info` | Filled only when the request was a scale barcode: `weight`, `total_price`, `is_weighted`. |
| `matched_variant_id` | The variant a scanned barcode belongs to, so the POS can preselect it. |
| `stock[]` | One row per stock batch in the store (see below). |
| `sale_units[]` | Extra sale units (pack, box). `conversion_rate` is how many base units one sale unit holds. `price` is an optional fixed price for that unit. |
| `variants[]`, `variant_mode`, `has_variants` | Product variants (only when **PRODUCT_VARIANT_ENABLED** is on). Each variant has its own SKU, barcode, price, MRP and `variant_attributes`. |
| `deleted_product_ids` | Products deleted in the `updated_at_range`; the app removes them from its cache. |

### Stock row fields

| Field | Meaning |
|---|---|
| `id` | Stock id. Sent as `stock_id` on each order line. |
| `product_variant_id` | `null` = general stock, otherwise the variant this batch belongs to. |
| `quantity` | Quantity on hand (3 decimals). |
| `price`, `mrp`, `purchase_price` | Retail price, MRP and purchase price of this batch. |
| `tax_rate` | Tax rate used for this batch, for example `18.00`. A stock rate above 0 wins over product and category taxes. |
| `tax_include`, `tax_include_purchase` | Whether the selling price and the purchase price include tax. |
| `wholesale_price`, `wholesale_min_unit` | Wholesale price that applies when the line quantity is at least `wholesale_min_unit`. |
| `rack`, `expiry_date`, `pkg_mfg`, `date` | Rack, expiry, manufacture date and stock date. |
| `purchase_unit_id`, `purchase_qty` | The sale unit the batch was bought in, and how many. |
| `unit_prices` | Per-sale-unit prices for this batch: `{ "<sale_unit_id>": price }`. |

**Notes**

- Billing groups stock rows by the fields in master data `STOCK_GROUPING_FIELDS` (default price and unit). See [Stock API](/docs/api/stock).
- With **POS_HIDE_NONSTOCK_PRODUCT** on and stock tracking on, the app hides products, batches and variants with zero stock.
- The app sends locale only as a header for this endpoint (no `?locale=`).

## POST /api/v1/product/create-product

**Purpose:** creates a product and, when a quantity is given, its opening stock in the active store.

**Screens:** **Create New Product** quick form (Product List > **Add Product**), Billing **Add Product** on phones. **Save (F9)** saves and closes; **Save and Create (F8)** saves and clears the form for the next product.

### Request body

```json
{
  "name": "classic chicken bucket",
  "price": "220",
  "category_id": "19",
  "mrp": "250",
  "barcode": "111000465",
  "quantity": "50",
  "unit": "PC",
  "purchase_rate": 150.0,
  "conversion_rate_base": 1,
  "item_code": "CCB-01",
  "sku": "1001",
  "min_margin_percentage": 10,
  "min_margin_price": 20,
  "product_names": [
    { "language_id": 4, "name": "دلو دجاج كلاسيك" }
  ],
  "sale_units": [
    { "unit_id": 10599, "conversion_rate": 6, "price": 1200, "barcode": "111000466" }
  ],
  "store_id": 2
}
```

Values above are an example built from the demo menu (classic chicken bucket sells at 220.00 with MRP 250). Optional keys are only sent when filled.

| Field | Rule |
|---|---|
| `name` | Required. |
| `category_id` | Required, must exist. |
| `price` | Required. Tax-inclusive selling price. |
| `unit` | Required (unit name, from `list-units`). |
| `barcode` | Optional. Must be unique among active products **and** sale-unit barcodes of the company. |
| `item_code` | Optional, unique per company. |
| `purchase_rate`, `quantity` | Optional, ≥ 0. A quantity above 0 creates opening stock. |
| `supplier_id` | Optional. Used for the opening stock. If there is opening stock and no supplier exists in the company, the server returns `422` "No supplier found for opening stock". |
| `min_margin_percentage`, `min_margin_price` | Optional max-discount caps (≥ 0). |
| `product_names[]` | Optional translated names: `{ "language_id", "name" }`. Language ids come from `GET /api/v1/languages` (Arabic is `4` in the demo). The default name is always stored too. |
| `sale_units[]` | Optional. Each needs `unit_id` and `conversion_rate` > 0; `price` and `barcode` optional. A sale-unit barcode cannot equal the main barcode. Shown in the **Multi Sale Unit** section (only when **MULTI_SALE_UNIT_ENABLED** is on). |
| `variants[]` | Optional (with **PRODUCT_VARIANT_ENABLED**). Each: `sku`, `barcode`, `price`, `mrp`, `purchase_price`, `quantity`, `reorder_level`, `active`, `attributes[{product_prop_id, value}]`. A blank SKU is generated. |
| `sort_order` | Optional, integer ≥ 1. `0` is treated as "not set". |
| `store_id` | The active store. Opening stock goes here. |

### Response

`200` with `{ "status": "success", "message": "Product created successfully", "data": { … } }`. `data` has the same shape as one product in `list-products` (ids, names, props, stock, sale units, variants).

### Errors

| Code | When |
|---|---|
| 422 | `Validation failed` with field errors, for example `"barcode": ["The barcode has already been taken in sale units."]`, or `"quantity": ["Enter a quantity valid for the base unit."]` for a fractional quantity on a piece unit. |
| 401 | Missing or expired token. |

## POST `/api/v1/product/edit-product/{id}`

**Purpose:** updates a product. Every field is optional ("sometimes").

**Screens:** Edit product dialog from Product List and from Billing (needs permission `billing.product.edit`, or legacy `update_product`).

### Request body

```json
{
  "name": "classic chicken bucket",
  "slug": "classic-chicken-bucket",
  "price": 220,
  "mrp": 250,
  "purchase_price": 150,
  "category_id": 19,
  "barcode": "111000465",
  "unit": "PC",
  "unit_id": "3310",
  "store_id": 2,
  "sku": null,
  "min_margin_percentage": 0,
  "min_margin_price": 0,
  "sale_units": [],
  "variants": []
}
```

**Notes**

- An empty `sale_units` list removes all sale units. The app sends it only when it means that.
- A cleared max-discount field is sent as `0` ("no cap"). A cleared SKU is sent as `null`.
- Variants: omit `id` to create, pass `id` to update, pass `id` with `"_delete": true` to remove. Attributes are replaced on every save.
- Quantity cannot be edited here in a way that changes stock; use Adjust Stock instead (see [Stock API](/docs/api/stock)).

**Response:** `{ "status": "success", "message": "…", "data": { … product … } }`. Errors come back as `{ "status": "failed", "message": "…" }` with 422 for validation.

## POST /api/v1/product/delete-product

**Purpose:** soft-deletes a product and its stock rows.

**Screen:** delete action in Product List.

```json
{ "product_id": 25011 }
```

| Result | Response |
|---|---|
| Deleted | `200` `{ "status": "success", "message": "Product deleted successfully", "data": { "product_id": 25011 } }` |
| Not found | `404` `Product not found` |
| Product still has stock on hand | `422` with the server's "stock on hand" message. Adjust or withdraw the stock first. |

Deleted ids appear in `deleted_product_ids` of the next delta sync, so other counters drop the product too.

## GET /api/v1/product/generate-barcode

**Purpose:** returns the next free barcode built from the company's barcode prefix (company prop **CUSTOM_BARCODE_PREFIX**, default `111000`).

**Screen:** generate button next to **Barcode** on Create New Product.

**Auth:** bearer token required. The app adds `store_id`.

Captured response:

```json
{
  "status": "success",
  "message": "Barcode generated",
  "data": { "barcode": "111000465" }
}
```

If no prefix is configured the server answers `400` "Barcode prefix not configured or inactive".

## GET /api/v1/calculate-tax

**Purpose:** the server's tax result for one price. The app calls it while adding stock to fill the tax amount fields.

| Param | Example | Rule |
|---|---|---|
| `price` | `220` | Required. |
| `product_id` | `3` | Required. |
| `tax_include` | `1` | Required. `1` = the price already includes tax, `0` = tax is added on top. |
| `category_id` | `2` | Optional. |

Captured response (tax disabled for that product, so the rate is 0):

```json
{
  "status": "success",
  "message": "Tax Calculated",
  "data": {
    "initial_price": 200,
    "tax_rate": 0,
    "tax_amount": 0,
    "price_excluding_tax": 200,
    "price_including_tax": 200
  }
}
```

### How the rate is chosen

1. If company setting **TAX_ENABLED** is off, tax is 0.
2. The stock row's `tax_rate`, when it is above 0.
3. Tax ids passed with the request.
4. Product taxes valid on that date.
5. Category tax, only when the product has no tax of its own.

A parent tax's rate is added to its child's rate. Amounts are rounded to 3 decimals by the server.

### Tax-inclusive formula, with the demo numbers

For a tax-inclusive price: `tax = price × rate / (100 + rate)` and `price without tax = price − tax`.

| Line | Price | Rate | Line total | Tax in line |
|---|---|---|---|---|
| classic chicken bucket × 2 | 220.00 | 18% | 440.00 | 440 × 18 / 118 = **67.12** |
| crispy chicken bucket × 1 | 218.00 | 18% | 218.00 | 218 × 18 / 118 = **33.25** |
| **Order** | | | **658.00** | **100.37** (net without tax 557.63) |

So `calculate-tax?price=220&tax_include=1` for an 18% product gives `tax_amount` 33.559 and `price_excluding_tax` 186.441 (the server keeps 3 decimals; the POS rounds money to 2 decimals).
