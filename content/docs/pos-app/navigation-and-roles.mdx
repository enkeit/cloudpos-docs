# Navigation and Roles

The menu shows only the items your role allows. If a colleague sees a menu item that you do not, your role is missing that permission. Only an administrator can change roles, in the admin panel.

## Moving around the app

- **Desktop and tablet:** the sidebar on the left. Items with a ▸ open a sub-menu. You can collapse the sidebar to icons and expand it again.
- **Phone:** tap the menu icon to open the drawer. Items are grouped under **Main**, **Sales**, **Inventory**, **Reports**, **Accounts**, **Directory** and **Settings**. The **AI** assistant button sits in the same row as **Logout**.
- **Phone billing** has a bottom bar: **Market** (product grid), **Billing**, **Order** and **Cart**.
- **Keyboard:** press **Ctrl+H** on billing to see all keyboard shortcuts. See [Billing](/docs/pos-app/billing).

![Keyboard shortcuts dialog](media:keyboard-shortcuts)

## The sidebar header and profile card

At the top of the sidebar is the **user switcher**. At the bottom is the **profile card** with your name, role and the **Active Store**.

![Sidebar with profile card and Active Store switcher](media:party-customer-transactions)
*Party Accounts > Customer Transaction: every customer debit/credit with amount, customer, type, reference ID and date filters; sidebar shows the profile card with Active Store switcher*

### Switch user

Use this when two cashiers share one till.

1. Tap your name at the top of the sidebar. The list of sales executives opens.
2. Pick the colleague. The dialog **Enter password for [name]** opens.
3. Your colleague types their password and taps **Switch**.
4. You see **Successfully switched to [name]**. New bills are now made under their name.

The switch is refused when the colleague has no access to the current store: "[name] doesn't have access to current store. Please logout and try." Permission: `menu.utility.user_switcher.access`.

### Switch store

1. Open the **Active Store** list on the profile card.
2. Pick another store you have access to.
3. The app clears the old store's cached products, categories and print layouts and runs the full store sync again. See [Getting started](/docs/pos-app/getting-started).

Permission: `menu.utility.store_switcher.access`. If you see **No stores assigned**, ask an admin to link you to a store.

## Which dashboard you see

The **Dashboard** menu item opens a different dashboard by role:

| Role | Dashboard |
|---|---|
| `sales_executive`, `restaurant_sales` | Sales Executive Dashboard (your own sales, your customers, ZATCA overview) |
| `supplier` | Admin dashboard |
| All other roles (including `company_admin`) | Company Admin Dashboard |

Each card on the dashboard also needs its own widget permission. See [Dashboard](/docs/pos-app/dashboard).

## Permissions inside screens

Some buttons inside a screen have their own permission:

| Permission | What it unlocks |
|---|---|
| `billing.product.view` | View product details from the billing screen |
| `billing.product.edit` (or legacy `update_product`) | Edit a product from the billing screen |
| `menu.purchase.orders.access` | See **purchase prices** anywhere in the app |
| `dashboard.widgets.<widget>.access` | Show one dashboard card (for example `dashboard.widgets.zatca_overview.access`) |
| `quotation.delete` | Delete a quotation (checked by the server) |
| role `sales_executive` or `restaurant_sales` | Packing and **Create Delivery** on order details |

Other roles:

- `delivery_executive` can sign in but has no POS permissions by default.
- `super_admin`, `customer`, `supplier`, `fc_executive`, `company_partner` and `customer_support` cannot sign in to the POS.
- There is no `cashier` or `admin` role. "Cashier" is only an employee designation.

## How it works

- After the store is chosen, the app downloads the company's roles (`GET /api/v1/roles/list`). It finds your role by name and reads its `permissions` list.
- A menu item is shown only when that list contains the item's permission string. Until the roles finish loading, permission-based items are hidden.
- Roles belong to one company. A company admin edits them in the admin panel under Roles. On free, trial, basic and demo packages, some permissions are locked.
- Changes made in the admin panel reach the device on the next store sync, or in **Settings → Offline Data → Roles & permissions → Sync**.
- **Logout** ends the session on the server and clears it on the device. If the server cannot be reached, you are still logged out on the device.
